Case

ThalaXYa
ThalaXYa is a brand-new tourist destination that has recently gained attention on the internet for its unique blend of tradition, culture, and modern experiences. As its popularity grows, ThalaXYa is expanding its reach into the digital world by launching various applications to enhance user interaction, simplify services, and build a stronger online presence. To support this initiative, the company has decided to develop a series of iOS applications under the ThalaXYa brand, each targeting different aspects of its ecosystem.
No.	Project Name	Project Description
1	ThalaXYa Fish Market	ThalaXYa Fish Market is an online marketplace for selling fish. There are 2 roles in this application. The admin can insert, update, and delete fish, where each fish has a name, weight, price, and the date it was added. The buyer can register and log in with email and password, top up their balance, and buy fish. The admin can view all transaction history, while the user can only view their own transaction.
2	ThalaXYa Course Account Manager	ThalaXYa Course Account Manager is an application to manage user accounts for an online course platform. There are 3 roles in this application: customer, trainer, and admin. Customers and trainers can register and log in using their email and password. A customer can apply to become a trainer by filling out their specialty, work shift, and age. Only the admin can view trainer applications and accept or reject them. Each user account consists of an email, password, name, and role, while each trainer account also includes their specialty, work shift, and age. The user can view all available trainers.
3	ThalaXYa Course	ThalaXYa Course is an online platform for managing courses. There are 2 roles in this application. The admin can insert, update, and delete courses, with each course having a name, trainer name, price, and duration. The customer can review courses, view all reviews they have submitted, and view all reviews for a course. The customer should register and log in using email and password.

 
All these applications have the same general requirements as follows:
1.	Views
•	The application must contain at least five views.
•	One of the views must be either a Table View Controller, or a Table View Layout.
•	The application should have four kinds of UI components.
2.	Data Source
•	The application should either use core data or file for the data storage.
•	The application should perform at least one data manipulation functionality (create, retrieve, update, and delete).
3.	Transition and Segue
•	All created views must have a transition.
•	There are at least 3 kinds of transition that should be used in the application.
4.	Data Validation
•	The application should have at least 3 kinds of data validations.
5.	Data Processing
•	The application should have at least 2 data processing or calculations.
6.	Creativity
•	The application should have a logo (xcassets file).
•	The application should be themed and involve changing 2 - 4 properties, such as font size, font family, font color, background color, tint, alpha, content mode, etc.
•	All customizations should be visible in the application and noted in the documentation.
•	The application should be usable, the design should not hamper usability of the application (e.g. font color and background color should have sufficient contrast, colors should not clash with each other).
7.	External Documentation
•	The application should include external documentation which explains the feature details and creativity in the application.
